# Project Brief

最終更新: 2026-04-07

## 誰の課題か
- 採用担当者: 候補者のフロントエンド実装力を短時間で判断したい。
- エンジニアリングマネージャー: 実装だけでなく、要件理解と設計意図を確認したい。
- クライアント: 依頼前に、解ける課題の範囲と品質水準を把握したい。

## 何の課題か
- 実績・スキル・連絡手段が分散しており、初回接触で評価材料が不足する。
- 見た目中心の紹介になりやすく、課題解決力と再現可能な開発プロセスが伝わりにくい。

## どう解くか
- 単一のポートフォリオサイトに「自己紹介」「実績一覧」「実績詳細」「スキル」「問い合わせ導線」を統合する。
- 実績詳細では、各案件の「課題」「担当範囲」「実装内容」「成果」を固定フォーマットで示す。
- 主要導線を「トップ → 実績詳細 → 問い合わせ」に統一し、評価から連絡までを短縮する。

## 価値仮説
- 初回訪問者が3分以内に、スキル適合性と依頼可否を判断できる。
- 採用・案件相談の問い合わせ率が、SNS単体プロフィール導線より改善する。

## 成功イメージ
- 履歴書、職務経歴書、SNS、営業資料で同一URLを提示できる。
- 代表実績の理解に必要な情報欠落がなく、面談前の認識合わせコストが下がる。
