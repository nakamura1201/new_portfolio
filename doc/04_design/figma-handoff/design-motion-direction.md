# Design Motion Direction

最終更新: 2026-04-20

## 1. モーションの役割
- このサイトのモーションは演出ではなく、状態変化の理解補助に使う。
- 主目的は「どこが押せるか」「何が切り替わったか」「次に何を見るべきか」を短時間で伝えること。
- 情報理解を遅らせる長尺アニメーションは使わない。
- 全体として、モダンで上質に見える範囲に留め、安っぽい動きは避ける。

## 2. モーション原則
- 速い: 基本は短く、反応の遅さを感じさせない。
- 小さい: 移動距離は最小限に抑え、位置関係を崩さない。
- 同時すぎない: 主要変化と補助変化を分け、視線誘導を壊さない。
- 一貫: hover / focus / open / close / loading の振る舞いを横断で揃える。
- 滑らか: カクついた段階変化や、安い印象の bounce 系は使わない。

## 3. 基本パラメータ
- Hover / focus 反応: 120ms-160ms
- Open / close / header state change: 160ms-220ms
- Loading / skeleton / progress hint: 600ms 以上の待ち時間が見込まれる場合のみ
- Easing は `ease-out` 系を基本とし、開始で溜めすぎない
- 大きな移動は使わず、opacity・color・shadow・短距離 translate を中心にする

## 4. 使いどころ
### 4.1 画面遷移
- ページ全体の派手なトランジションは不要。
- 遷移時はスクロール位置、見出し、CTAの認識を阻害しないことを優先する。

### 4.2 状態変化
- hover / active / focus は、色・境界線・影・わずかな位置変化で即時に伝える。
- scrolled header は高さや背景の変化を短く滑らかに見せる。
- card hover は浮遊感より「選択可能性」を伝える軽い反応に留める。

### 4.3 フィードバック
- CTA押下時は、押せたことが即時に伝わる反応を持たせる。
- フォーカスリングは消さず、視認性を高く保つ。
- フォーム導線に error がある場合は、色変化を主とし、揺れ演出は使わない。

### 4.4 メインビジュアル
- メインビジュアルに動きを入れる場合は、短い視線誘導または奥行き補助に限定する。
- 常時ループで目立ち続けるアニメーションは避ける。
- 3D表現は使用可。ただし、情報理解を邪魔せず、質感が安っぽく見えない場合に限る。
- 3Dを使う場合も、過度な回転、派手な発光、ゲーム的な演出にはしない。

## 5. コンポーネント別方針
### 5.1 `cmp/nav/header`
- default -> scrolled: 背景、影、余白の変化を 180ms-240ms で処理
- mobile メニューを出す場合は、短い fade + slide 程度に抑える
- active-link は位置移動より色や下線で示す

### 5.2 `cmp/button/cta`
- hover: 色、境界、影、translateY 数px 未満
- active: hover より短く、押し込みを感じる反応
- focus: 影より focus ring 優先
- disabled: 動かさない。色とコントラスト差で無効を示す
- loading: ボタン幅は維持し、ラベルの急なジャンプを避ける

### 5.3 `cmp/card/project`
- hover: 120ms-180ms の軽い浮きまたは境界強調
- focus: hover と同等以上に明確
- カード全体を大きく動かさず、詳細導線の存在を補強する

### 5.4 `cmp/section/project-detail`
- セクション出現は必要なら短い fade-up 程度
- 読解中心のため、連続スクロールで目障りな視差や遅延出現は避ける

### 5.5 `cmp/block/skill-category`
- hover が必要な場合でも最小限
- 習熟度表示はアニメーションで盛らず、読み取りやすさを優先

### 5.6 `cmp/footer/base` / `cmp/link/contact`
- CTA系と同じルールに揃える
- footer だけ別演出にしない

## 6. パフォーマンス制約
- 初回主要表示 3 秒以内の非機能要件を優先し、ファーストビューで重い演出を入れない。
- box-shadow や blur の過剰アニメーションは避ける。
- レイアウト再計算を伴う大きな高さ変更より、opacity / transform / color を優先する。

## 7. アクセシビリティ
- `prefers-reduced-motion` 時は、移動アニメーションを削減し、fade または即時変化へ置き換える。
- hover 依存にせず、focus-visible で同等の理解ができること。
- 情報伝達を動きだけに依存させない。色、ラベル、境界も併用する。
- reduce motion 時は、メインビジュアル上のモーションや 3D の動きも停止または極小化する。

## 8. 禁止演出
- 300ms を超える hover 反応
- 大きな parallax、長距離 slide、常時ループする装飾アニメーション
- bounce、elastic など業務ポートフォリオと相性の悪い過剰な反発
- 安っぽい印象を与える、過剰な 3D 回転や演出目的の浮遊表現
- 文字の分解出現、可読性を損なう stagger 多用
- error 状態の強い shake や点滅

## 9. Figma担当者・実装担当者への補足
- motion token として duration / easing / elevation change を定義し、コンポーネント横断で再利用できるようにする。
- Dev Handoff では interaction duration / easing / transformed properties を明記する。
- 迷った場合は「動きを減らしても意味が残るか」を判断基準にする。
