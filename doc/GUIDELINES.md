# ドキュメント作成ガイドライン

このガイドラインは、`doc` フォルダ内のドキュメントを作成・管理する際のルールを定義します。

## 1. ディレクトリ構成

```text
/doc
  /01_overview     ... プロジェクト概要（目的、スコープ、用語集）
  /02_research     ... 調査・分析資料（競合調査、技術選定理由）
  /03_requirements ... 要件定義（機能要件、非機能要件）
  /04_spec         ... 仕様書（画面仕様、API仕様）
  /05_design       ... 設計資料（IA、ワイヤーフレーム）
  /99_archive      ... 旧資料・参考資料（アーカイブ）
```

## 2. ファイル命名規則

- **小文字 + ハイフン区切り**: `project-brief.md`, `api-spec.md`
- **日本語ファイル名は避ける**: 検索性と Git 互換性のため

## 3. 各ディレクトリの役割と必須ファイル

### 01_overview（概要）

| ファイル             | 内容                                         |
| -------------------- | -------------------------------------------- |
| `project-brief.md`   | 誰の、何の課題を、どう解くか（1 ページ要約） |
| `goals-non-goals.md` | プロジェクトのゴールと明示的な非ゴール       |
| `scope.md`           | 対象範囲（含むもの・含まないもの）           |
| `glossary.md`        | 用語統一（認識ズレ防止）                     |

### 02_research（調査）

- 競合サイト分析
- 技術選定の根拠
- ユーザーインタビュー結果

### 03_requirements（要件）

- 機能要件一覧
- 非機能要件（パフォーマンス、セキュリティ）
- 優先度マトリクス

### 04_spec（仕様）

- 画面仕様書
- コンポーネント仕様
- API 仕様（エンドポイント、リクエスト/レスポンス）

### 05_design（設計）

- 情報アーキテクチャ（IA）
- ワイヤーフレーム
- デザインシステム参照

### 99_archive（アーカイブ）

- 過去バージョンのドキュメント
- 参考資料
- 一時的なメモ

## 4. ドキュメント作成ルール

1. **Markdown で記述**: 全てのドキュメントは `.md` 形式で作成すること。
2. **見出し構造**: `# H1` はファイルタイトルのみ。本文は `## H2` 以下を使用。
3. **更新日を記載**: 冒頭に `最終更新: YYYY-MM-DD` を記載すること。
4. **リンクは相対パス**: 他ドキュメントへのリンクは相対パスで記述。

## 5. 移行ルール

- 完成したドキュメントは適切なディレクトリへ移動。
- 不要になった資料は `99_archive` へ移動（削除は極力避ける）。

## 6. エージェントへの指示

AI エージェントがドキュメントを作成・編集する際は、このガイドラインを参照し、適切なディレクトリに正しいフォーマットでファイルを作成すること。
