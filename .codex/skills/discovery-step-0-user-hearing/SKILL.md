# Step 0 ユーザーヒアリング

## 出力
- `doc/05_marketing/01_product_marketing/step-00-ユーザーヒアリング/ヒアリング設計.md`
- `doc/05_marketing/01_product_marketing/step-00-ユーザーヒアリング/ヒアリングログ.md`
- `doc/05_marketing/01_product_marketing/step-00-ユーザーヒアリング/示唆サマリー.md`

## 手順
1. ヒアリング目的を定義し、確認したい仮説を3-5個に絞る。
2. ユーザー属性、現状行動、課題、代替手段、支払い意思を確認する質問セットを作る。
3. 最低3件のヒアリング結果をログ化し、共通パターンと差分を抽出する。
4. 次工程（発散と構造化）へ渡す「優先課題候補」と「探索の制約条件」を明文化する。

## 判断ポイント（ユーザー確認）
1. ヒアリング設計完了時
- 確認項目: 質問の過不足、仮説の妥当性、対象ユーザーの妥当性。
- 進行条件: ユーザーが質問セットを承認する。

2. ヒアリングログ作成時
- 確認項目: 事実と解釈の分離、抜け漏れ、偏りの有無。
- 進行条件: ユーザーが主要ログの品質を承認する。

3. 示唆サマリー作成時
- 確認項目: 優先課題候補、成功条件、除外条件が妥当か。
- 進行条件: ユーザーが次工程へ渡す論点を確定する。

## 完了条件
- ヒアリング設計、ログ、示唆サマリーが揃っている。
- ブレスト前提として「誰の何の課題を優先するか」が説明できる。
