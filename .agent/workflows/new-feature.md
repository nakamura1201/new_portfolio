# 新規機能・ページ作成ワークフロー

新しい機能コンポーネントやページを作成する際は、以下の手順に従ってください。
このワークフローは、プロジェクトの Skills（知識）を最大限に活用し、手戻りを防ぐために設計されています。

## 1. 要件と設計の確認

ユーザーに以下の点を確認する（明確でない場合）：

- **種類**: 新規ページ（Project）か、再利用可能な部品（Component）か？
- **機能**: アニメーションや動的な挙動（JS）は必要か？

## 2. アーキテクチャの適用

`.agent/skills/front_end_architecture/SKILL.md` を読み込み、以下を決定する：

- **レイヤー**: `layout`, `component`, `project` のどれに該当するか。
- **ファイルパス**: `/assets/scss/` 配下のどこに配置すべきか。
- **命名規則**: BEM に基づいたクラス名（例: `.p-about-company`, `.c-btn--primary`）。

## 3. 実装の実行

決定した設計に基づき、ファイルを生成する。

1. **SCSS ファイルの作成**:

   - `_filename.scss` を作成。
   - 親ファイル（`style.scss` または `_index.scss`）に `@use` を追加。
   - **重要**: スキルに従い、BEM クラス名のみを使用すること。

2. **PHP/HTML の作成**:

   - PHP テンプレートや HTML を作成し、定義した BEM クラスを適用。

3. **JS/アニメーションの実装（必要な場合）**:
   - `.agent/skills/interactive_motion/SKILL.md` を読み込む。
   - GSAP/Lenis/Splide など、推奨ライブラリを使用して実装。
   - 「プレミアム」な品質基準（イージング、マイクロインタラクション）を満たすこと。

## 4. 自己チェック

作成後、以下の項目を確認する：

- [ ] クラス名は BEM 規約に違反していないか？（`Code Review Skill` の観点）
- [ ] SCSS ファイルは適切に `@use` され、コンパイルエラーが出ていないか？
- [ ] 意図した通りのデザイン・挙動になっているか？
