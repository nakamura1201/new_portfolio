# Figma デザインデータ取り込みスキル

Figma MCP サーバーを通じてデザインファイルの構造化データを取得し、
プロジェクトの `doc/04_design/DESIGN.md` にデザインシステム仕様としてまとめるスキルです。

---

## 前提条件

このスキルを使用するには以下が必要です：

1. **Figma MCP サーバーが接続済み**であること
   - 公式リモート MCP: `https://mcp.figma.com/mcp`
   - または Figma Desktop MCP
2. **対象の Figma ファイル URL**をユーザーから提供されること
   - 形式: `https://www.figma.com/design/<FILE_KEY>/...`
3. MCP クライアント（エージェント環境）から Figma MCP ツールが呼び出せること

> **注意**: Figma MCP ツールが利用不可の場合は、ユーザーにその旨を伝え、
> 手動でデザイントークンを入力してもらう代替フローに切り替えてください。

---

## 実行手順

### ステップ 1: Figma ファイル URL の取得

ユーザーに対象の Figma ファイル URL を確認します。

```text
対象の Figma ファイル URL を教えてください。
例: https://www.figma.com/design/XXXXXXXXXX/Project-Name
```

URL から `FILE_KEY` を抽出します（`/design/` 以降の英数字部分）。

特定のページやフレームに限定したい場合は、`node-id` パラメータも確認します。

---

### ステップ 2: デザインデータの取得

Figma MCP サーバーの各ツールを使い、以下のデータを順に取得します。

#### 2-1. ファイル全体の構造を把握

**公式 Figma MCP の場合:**

```
ツール: get_design_context
目的: ファイル全体のページ構成・フレーム階層を把握する
```

**コミュニティ MCP (enyonee/figma-mcp 等) の場合:**

```
ツール: get_file
目的: ファイルのドキュメントツリーを取得する
```

取得するべき情報:
- ページ一覧とその構成
- 主要フレーム（画面）の名前とサイズ
- デザインの全体像

#### 2-2. デザイントークン・変数の取得

```
ツール: get_variable_defs （公式 MCP）
ツール: get_variables    （コミュニティ MCP）
```

取得するべき情報:
- **カラー変数**: プライマリ、セカンダリ、アクセント、背景、テキストなど
- **スペーシング変数**: マージン、パディングの基準値
- **フォントサイズ変数**: 各見出し・本文のサイズ定義
- **ブレイクポイント**: レスポンシブの閾値
- **その他のカスタム変数**: ボーダー、シャドウ、不透明度など

#### 2-3. スタイルの取得

```
ツール: search_design_system （公式 MCP）
ツール: get_styles            （コミュニティ MCP）
```

取得するべき情報:
- **カラースタイル**: HEX/RGBA 値、カラー名、用途
- **テキストスタイル**: フォントファミリー、ウェイト、サイズ、行間、文字間隔
- **エフェクトスタイル**: シャドウ、ブラーなど
- **グリッドスタイル**: カラム数、ガター幅、マージン

#### 2-4. コンポーネントの取得

```
ツール: search_design_system （公式 MCP）
ツール: get_components        （コミュニティ MCP）
```

取得するべき情報:
- **コンポーネント一覧**: 名前、説明
- **バリアント**: 各コンポーネントの状態・サイズバリエーション
- **コンポーネントの階層構造**: アトミックデザインのレベル分け（もし存在すれば）

#### 2-5. 各画面のスクリーンショット（任意）

```
ツール: get_screenshot （公式 MCP）
```

主要画面のスクリーンショットを取得し、`doc/04_design/screenshots/` に保存します。

---

## ステップ 4: SCSS 変数ファイルの更新（任意）

DESIGN.md の「SCSS 変数マッピング」セクションの内容を
`assets/scss/foundation/_variable.scss` に反映します。

> **注意**: 既存の変数ファイルがある場合は、差分を確認してからマージしてください。

## ステップ 5: レビューと確認

1. 生成した DESIGN.md をユーザーに提示し、レビューを依頼する。
2. 以下のチェックリストで確認:

- [ ] 全てのカラーが HEX 値で正しく記載されているか
- [ ] フォントファミリー・サイズが Figma と一致しているか
- [ ] スペーシングの値が正確か
- [ ] コンポーネント一覧に漏れがないか
- [ ] ブレイクポイントが正しく定義されているか
- [ ] SCSS 変数名がプロジェクトの命名規則（FLOCSS）に沿っているか

---

## トラブルシューティング

### Figma MCP ツールが使用できない場合

MCP サーバーが接続されていない環境では、以下の代替手段を提案してください：

1. **Figma の Inspect パネル**からデザイントークンを手動で抽出してもらう
2. **Figma の CSS エクスポート機能**で値を取得してもらう
3. ユーザーが提供する**スクリーンショットやデザインガイド PDF** を元に記述する

### 取得データが不完全な場合

- Figma ファイルの構造化が不十分（変数・スタイル未定義）な場合があります
- その場合は、取得できた情報のみで DESIGN.md を作成し、不足箇所を `[要確認]` として明記します
