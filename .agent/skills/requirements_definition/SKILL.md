# 要件定義スキル

このスキルは、`doc/GUIDELINES.md` に準拠した要件定義ドキュメントを作成する手順を定義します。

## 1. 事前準備

要件定義を開始する前に、以下の情報を収集してください。

- **プロジェクト概要**: `doc/01_overview/project-brief.md` を確認。
- **スコープ**: `doc/01_overview/scope.md` を確認。
- **用語集**: `doc/01_overview/glossary.md` を確認し、用語のブレを防ぐ。

## 2. 出力先

要件定義ドキュメントは以下のディレクトリに作成します。

```text
doc/03_requirements/
  ├── functional-requirements.md   ... 機能要件
  ├── non-functional-requirements.md ... 非機能要件
  └── priority-matrix.md           ... 優先度マトリクス
```

## 3. 機能要件の書き方

`functional-requirements.md` のテンプレート：

```markdown
# 機能要件一覧

最終更新: YYYY-MM-DD

## FR-001: [機能名]

- **概要**: [1 行で説明]
- **詳細**: [具体的な振る舞い]
- **関連画面**: [該当する画面名]
- **優先度**: 高 / 中 / 低

## FR-002: [機能名]

...
```

### 記述ルール

- ID は `FR-XXX` 形式で連番管理。
- 1 機能 = 1 セクション。複数の振る舞いがある場合は箇条書きで分ける。
- 曖昧な表現（「など」「適切に」）を避け、具体的に記述する。

## 4. 非機能要件の書き方

`non-functional-requirements.md` のテンプレート：

```markdown
# 非機能要件一覧

最終更新: YYYY-MM-DD

## NFR-001: パフォーマンス

- **基準**: ページ読み込み時間は 3 秒以内

## NFR-002: セキュリティ

- **基準**: XSS 対策として全出力をエスケープすること

## NFR-003: アクセシビリティ

- **基準**: WCAG 2.1 AA 準拠
```

### カテゴリ例

- パフォーマンス
- セキュリティ
- 可用性
- 保守性
- アクセシビリティ

## 5. 優先度マトリクスの書き方

`priority-matrix.md` で、要件の優先順位を可視化します。

```markdown
# 優先度マトリクス

| ID     | 要件名       | 重要度 | 緊急度 | 優先度 |
| ------ | ------------ | ------ | ------ | ------ |
| FR-001 | ログイン機能 | 高     | 高     | 1      |
| FR-002 | お問い合わせ | 高     | 中     | 2      |
| FR-003 | SNS シェア   | 低     | 低     | 5      |
```

## 6. レビューチェックリスト

要件定義完了後、以下を確認してください。

- [ ] 全ての機能要件に一意の ID が付与されているか
- [ ] 曖昧な表現がないか
- [ ] 非機能要件が漏れていないか（特にセキュリティ）
- [ ] 優先度が設定されているか
- [ ] 用語が glossary.md と一致しているか
